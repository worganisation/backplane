# Manual capture model evaluation

Run `uv run python -m scripts.dev.evaluate_capture` from the repository to evaluate the local Ollama model named in `deploy/capture-assist.json`. The command uses Backplane's validated application settings, including `OLLAMA_BASE_URL` (the OpenAI-compatible `/v1` URL) and `LOCAL_TIMEZONE`. Normal application configuration, including `OBSIDIAN_VAULT_PATH`, is required, but no vault content is read or written. Development dependencies must be installed with `uv sync`.

The runner sends the actual `deploy/capture-prompt.jinja` and registered Capture tool schemas to Ollama. Each fixed scenario is a separate conversation, anchored to 18 October 2026 so relative dates remain comparable. It checks tool routing, required argument schemas including diary date formats, operation-key prefixes, explicit projects/priority/deadlines, original factual wording, and whether ambiguity produces a question without a capture. Proposed tool calls are never executed. The runner does not contact Home Assistant or send live notifications.

Use `uv run python -m scripts.dev.evaluate_capture --dry-run` to inspect the cases and rendered prompts without contacting Ollama. Use `--model qwen3:4b-instruct` to compare another locally available model. The command uses Ollama's [OpenAI-compatible chat endpoint](https://docs.ollama.com/api/openai-compatibility), temperature zero, a 1,024-token response limit and a 120-second timeout per scenario. It does not pull models or retry failed requests.

JSON on standard output records the model, prompt/schema hashes, individual responses, elapsed times and violations; progress goes to standard error. Save a report with `uv run python -m scripts.dev.evaluate_capture > capture-evaluation.json`. Exit status is zero for passing checks or a dry run, and one when any scenario fails. Reports contain only the checked-in synthetic corpus and model responses, but review output before sharing it.

These deterministic checks are a small smoke evaluation, not an LLM judge or proof of reliable voice capture. Inspect the proposed text and clarification questions yourself: a question mark alone cannot establish that a question is useful. The command does not test speech recognition, multi-turn retry behavior, live HA pipeline configuration, or persistence. It is opt-in and is not run against a model by CI.
